# Valen：UMD 76 张图训练复现

训练使用 OOAL 作者选定的 **76 张 novel/train 图像**，每个训练实例 1 张（32 张人工标注、44 张自动标注）；测试为 **2661 张 novel/test 人工标注图像**。训练与测试的图片、实例、物体类别均不重叠。

训练读取原始 `*_label.mat` 的 `gt_label`：0 为背景，1–7 为功能类别，-1 忽略。每个 PartGLEE 候选按有效 GT 像素的多数类别监督，平票取较小类别 ID。**候选形状不使用 GT；不做 ladle 的 contain→scoop 重映射。**

## 准备

按项目 [README](../README.md) 安装项目外的 Conda 虚拟环境、补全权重和官方 UMD 数据。这里不复制或迁移 Conda 环境。

| 文件 / 目录 | 用途 |
|---|---|
| `data/UMD/part-affordance-dataset/` | 官方 `tools/`、`novel_split.txt` 等原始数据 |
| `configs/umd_train_76.json` | 固定 76 张选择、RGB/MAT SHA256、官方划分 SHA256 |
| `configs/umd_pipeline.json` | 前景选择、候选分割与去重参数 |
| `configs/umd_affordances.json` | UMD 七类功能及 none 的定义 |
| `configs/valen_76_sft.json` | 普通 SFT 的训练参数 |
| `configs/valen_76_abc/*.json` | 单卡 SFT 对照及 A/B/C 参数 |

76 张选择已与作者 one-shot 数据逐像素核验，核验来源记录在选择配置中。新机器按固定哈希验证官方 RGB/MAT 即可，**不依赖 OOAL 仓库、DINO 权重或旧实验 outputs**。

各脚本顶部可直接修改数据、配置、模型、输出路径及 `CUDA_VISIBLE_DEVICES`。环境默认使用 `$HOME/miniconda3/envs/partglee` 和 `valen-4b-sft`，安装位置不同则修改 `PYTHON`。

## 生成训练输入

在仓库根目录执行：

```bash
bash scripts/prepare_umd.sh
bash scripts/prepare_valen_umd.sh
```

第一条生成完整测试清单；第二条依次完成：

1. 从原始数据重建固定 76 张训练清单，验证 RGB/MAT、官方划分及训练/测试无重叠。
2. PartGLEE 只读取训练 RGB，预测目标前景及不重叠候选 mask。
3. 生成三图输入、分类问题和训练 `records.jsonl`。GT 只写入监督目标，不进入模型输入。
4. 从这 76 张图生成 A/B 的显示、定义及几何变体；只训练普通 SFT 时可将 `PREPARE_ABC_VIEWS=false`。

默认产物：

```text
data/UMD/manifests/ooal_novel_train_76.jsonl
outputs/valen_76/train_candidates/                 # 原候选及分割过程
outputs/valen_76/train_fill_dominant/records.jsonl   # 76 条训练记录
outputs/valen_76_abc/training_views/a_records.jsonl  # A：每图 4 个变体
outputs/valen_76_abc/training_views/b_records.jsonl  # B：每图 4 个变体
```

已有清单只校验；候选、记录和变体目录非空时拒绝覆盖。旧机器重复实验请修改脚本顶部输出目录，并同步修改训练脚本的输入路径。清单和记录会写入本次机器的实际路径，换机器后应重新生成；不直接搬用旧 `outputs` 中的绝对路径记录。

## 普通 SFT

```bash
bash scripts/train_valen_umd.sh
```

固定 seed=321；先进行 **300 步分类头预热**，再进行 **1000 步语言模型 LoRA＋分类头联合训练**。LoRA r=8、alpha=16、dropout=0.05；头学习率 1e-4，LoRA 学习率 1e-5；有效源图 batch=4。视觉编码器、视觉 merger 和基座参数冻结。

脚本默认单 GPU 梯度累积（`NUM_PROCESSES=1`）。历史首轮 S0 使用四卡 DDP；要恢复该并行方式，将脚本顶部改为：

```bash
NUM_PROCESSES=4
export CUDA_VISIBLE_DEVICES=0,1,2,3
```

预热始终使用单进程；联合训练在多卡时通过 `torch.distributed.run` 启动。多卡分支保留历史 4090 的 `NCCL_P2P_DISABLE=1`、`NCCL_IB_DISABLE=1` 主机通信设置，其它主机可按硬件调整。有效 batch 仍为 4，训练步数、学习率等从配置读取。

A/B/C 入口仍为单卡；其同条件普通 SFT 对照使用下述 `s0r.json`。入口保存本次实际配置。

默认日志在 `outputs/valen_76/s0/321/`，预热权重在 `checkpoints/valen_76/s0/321/warmup/`，最终权重在同级 `final/`。支持单独执行 `warmup` 或在预热完成后执行 `joint`：

```bash
bash scripts/train_valen_umd.sh warmup
bash scripts/train_valen_umd.sh joint
```

## A/B/C

先准备上述训练输入和同一份 300 步预热头；无需先完成普通 SFT 的 1000 步联合训练。

在 `scripts/train_valen_abc.sh` 顶部选择 `TRAIN_CONFIG`，填写本方案的 `OUTPUT_DIR`、`CHECKPOINT_DIR`，然后执行：

```bash
bash scripts/train_valen_abc.sh
```

| 配置 | 训练方法 |
|---|---|
| `s0r.json` | 同单卡、同梯度累积方式的普通 SFT 对照 |
| `a0.json` / `a1.json` | 相同显示/定义增强；A1 增加区域与定义配对、预测一致性 |
| `b0.json` / `b1.json` | 相同拆分/合并及组成监督；B1 增加组成一致性 |
| `c0.json` / `c1.json` | C0 添加目标区域特征；C1 再加入最近邻和整物体特征 |

所有方案复用同一预热头，重新初始化 LoRA，固定训练 1000 步。A/B 每个源图使用两次骨干前向，S0R/C 使用一次；训练计算量不同。B 的辅助头仅用于训练，C 的区域头用于训练和推理。

最终目录含 `head.safetensors`、`adapter/` 及训练配置；B/C 另存 `extra_heads.safetensors`。推理时保留完整目录，由推理入口按方案加载。新入口不自动启动评测、不使用测试集选权重；最终模型固定取第 1000 步。
