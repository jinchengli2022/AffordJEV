# 环境安装

**Conda 环境保留在仓库外。** 仓库只记录依赖和安装步骤；不复制环境，也不改变当前机器已有的包。

## 已验证的版本

| 环境名 | 用途 | Python | PyTorch / torchvision | Transformers |
|---|---|---|---|---|
| `partglee` | 前景与部件候选分割 | 3.10.22 | 2.2.2+cu121 / 0.17.2+cu121 | 4.36.0 |
| `valen-4b-sft` | 区域分类、SFT/LoRA、评测与可视化 | 3.11.16 | 2.7.1+cu126 / 0.22.1+cu126 | 5.4.0 |

两个环境通过中间文件衔接，避免混装不兼容的 Transformers。Valen 的同一环境支持推理和训练。

适用平台为 **Linux x86_64＋NVIDIA GPU**。需要 Conda、支持上述 CUDA 运行库的 NVIDIA 驱动，以及供 PartGLEE 编译扩展使用的 CUDA 12.x Toolkit（含 `nvcc`）、GCC/G++。当前参考机器为 RTX 4090、CUDA Toolkit 12.4、GCC 9.4.0。PyTorch 自带 CUDA 运行库，**不会提供 `nvcc` 编译器**。

OpenCV 保留已验证的 `opencv-python==4.11.0.86`。精简服务器若提示缺少 `libGL.so.1` 或 GLib，需要先安装系统的 `libgl1`、`libglib2.0-0`；不要再并装另一个 `opencv-python-headless` 覆盖同名模块。

## 新主机安装

在克隆后的 `AffordanceJEV` 根目录运行：

```bash
# 如 nvcc 不在 PATH，先按本机实际位置设置：
export CUDA_HOME=/usr/local/cuda

bash scripts/setup.sh all
```

脚本用 `conda create -n` 创建外部环境；依次安装固定版本 PyTorch、其余依赖，再编译本仓库 PartGLEE 的 Detectron2 与 `MultiScaleDeformableAttention`。生成的 `.so` 与当前 Python/PyTorch/GPU 相关，应在新主机编译，不随 Git 分发。

可分别安装：

```bash
bash scripts/setup.sh partglee
bash scripts/setup.sh valen
```

**若同名环境已存在，安装立即停止，不覆盖、不删除。** 已有环境只需检查：

```bash
bash scripts/setup.sh check
```

需要另起环境名时，在命令前设置 `PARTGLEE_ENV`、`VALEN_ENV`，并同步修改各运行入口顶部的环境设置。安装中断后不会自动删除半成品环境；修复原因后可自行选择新名称。

有本机代理时，可临时使用：

```bash
HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890 bash scripts/setup.sh all
```

## 版本清单与计算路径

- `requirements/partglee.txt`、`valen.txt`：该路径所需的直接依赖。
- `requirements/constraints-*.txt`：从已运行环境提取的传递依赖版本约束，避免安装时自动升级。
- `requirements/observed-*.json`：原环境的完整版本记录，仅用于追溯，不是要求全部安装。
- `src/affordance_jev/deployment/check_environment.py`：只检查版本、CUDA、扩展导入和计算路径；不下载权重、不启动推理或训练。

PartGLEE 使用本仓库附带的源码，`pip install --no-build-isolation --no-deps` 让扩展针对已安装的 PyTorch 编译。`--no-deps` 不代替前面的依赖安装。旧 Detectron2 的元数据还声明 `black`、`future`、`pydot`，本分割路径不使用这三个工具，也与现有环境一样不安装；因此普通 `pip check` 会报告这三项缺失，专用检查会单独提示，不将其当作模型运行失败。

Valen 保留原实验的 **SDPA＋FLA 0.5.2**：线性注意力使用 FLA，因果卷积因未安装 `causal-conv1d` 而使用 PyTorch 回退。不要额外切换 Flash Attention 或安装 `causal-conv1d` 后仍把结果当成同一计算路径。

以上清单记录的是本项目的实际运行版本，和两个上游 README 的示例环境有区别。迁移保留模型、配置和输入输出规则；不同 GPU、驱动或并行执行条件仍可能产生浮点差异，不能承诺逐位相同。

环境检查通过后，按仓库权重清单补齐 `models/` 中资源，再进行单样本验证。仅安装环境不会下载数据集、模型权重或启动完整实验。
