# PartGLEE＋Valen 整体框架

**整体输入：RGB＋功能类别及其文字定义、判断规则＋物体／部件词表。整体输出：与 RGB 对齐的功能类别图、各功能二值 mask，以及候选的分类结果。**

核心思路：PartGLEE 提供部件边界，Valen 根据给定的功能定义判断部件类别，程序合并同类部件得到功能 mask。当前面向单个主要目标物体。

## 0. 系统输入与输出

文中的“RGB-only”仅说明**视觉观测使用 RGB，不使用深度**；完整系统仍需要下面的文字任务条件。

| 外部输入 | 内容与来源 | 用在哪里 |
|---|---|---|
| RGB 图片 | 每个待预测样本的原始 RGB | PartGLEE 分割、生成 Valen 的三张输入图 |
| 功能类别与文字定义 | 如 `grasp`＝专用抓握部位、`cut`＝切割工作面；由功能配置提供 | 作为 Valen 选择题的选项和判断依据 |
| 判断规则 | 每候选单标签、如何区分相近功能、何时选 `none` 等 | 与图片一起组成 Valen 的 Prompt |
| 物体／部件词表 | 如 `cup / knife`、`handle / blade`；由流水线配置提供 | PartGLEE 的文本类别输入，指导物体和部件候选生成 |

这些文字条件由配置统一提供，无需每张图重新填写。当前 UMD 向 Valen 提供 **7 种功能类别＋`none`**，让它为每个候选选择一类；不会提供该图的真实物体类别或正确功能标签。

**“功能区域”需要区分两层：功能含义由外部文字定义，候选区域的位置和形状由 PartGLEE 从 RGB 中预测。** 候选 mask 是系统内部中间量，也是 Valen 判断的对象；不需要用户先标出功能区域，正常推理不输入 GT mask。

| 阶段 | 实际输入 | 输出 |
|---|---|---|
| PartGLEE 物体分割 | 完整 RGB＋配置中的物体／部件词表 | 整物体候选 mask、候选类别及质量分数，再选出目标前景 |
| PartGLEE 部件分割 | 前景外置灰的目标裁剪图＋同一套词表 | 部件候选 mask，经整理得到最多 6 个互斥候选 |
| Valen 功能判断 | 原色裁剪图＋候选可视化＋功能定义、判断规则和逐候选选择题 | 每个候选的功能类别及各选项概率 |
| 程序合并 | 候选二值 mask＋Valen 分类结果 | 原图尺寸的功能类别图和各功能二值 mask |

**标准方案中，Valen 通过编号／高亮图看到候选区域；二值 mask 数组由程序保留，用于最后合并。** Valen 输出类别判断，最终像素边界来自 PartGLEE 候选。

下面的流程图以原始填色基线为例：

```mermaid
flowchart TD
    A[完整 RGB] --> B[PartGLEE 第一次推理：整物体候选]
    V[配置输入：物体／部件词表] --> B
    B --> C[按质量、面积、位置选出一个目标物体]
    C --> D[物体外置灰，裁剪目标及少量边距]
    D --> E[PartGLEE 第二次推理：50 个部件候选]
    V --> E
    E --> F[限制在物体内、过滤、处理重叠，保留最多 6 个候选]
    A --> G[原色裁剪图]
    F --> H[全部候选编号图＋逐候选高亮拼图]
    G --> I[Valen：三张图＋功能定义＋逐区域选择题]
    H --> I
    T[配置输入：功能类别、文字定义、判断规则] --> I
    I --> J[每个候选的功能类别＋各选项概率]
    F --> K[将同类候选 mask 取并集]
    J --> K
    K --> L[原图尺寸的功能类别图及各功能二值 mask]
```

## 1. 先确定目标物体与背景

PartGLEE 首次接收完整 RGB，产生 **50 个整物体候选**。mask 概率大于 0.5 的像素视为候选内部。

候选质量分数为：`类别 sigmoid 分数 × mask 内部平均 sigmoid 分数`。这是模型分数，不是实测 IoU。

排除质量分数低于 0.01、面积小于 64 像素的候选后，按以下规则选出一个：

```text
排序分数 = 质量 × √(候选面积 / 图像面积) × 中心位置权重 × 边缘惩罚
```

中心位置权重使用候选包围框中心，越靠近画面中心越大；碰到图像边缘时乘 0.1。该规则假设目标通常较完整且靠近中心，可能误选大面积背景。

- 选中 mask 内是当前目标前景，外部是背景；场景中的其他物体也可能被排除。
- 无合格候选时记录失败，不使用 GT 补救。
- 分割使用固定物体词表，包括 UMD 物体名称；不传入当前图片的真实物体类别。

## 2. 分割目标的部件

把目标 mask 外像素置为灰色 127，再按目标包围框裁剪。每侧额外边距为包围框较长边的 10%，受原图边界限制。

PartGLEE 第二次接收这个灰背景裁剪图，产生 **50 个允许相互重叠的部件候选**。使用统一部件词表，如 handle、blade、interior surface；这些部件名称不直接作为最终功能标签。

将候选映射回原图坐标，并与选中的目标物体 mask 取交集。第一步漏掉的物体区域，后续候选与 Valen 都无法补回。

## 3. 整理重叠候选

此时尚未判断功能类别。目标是得到数量较少、像素互斥的候选。

| 操作 | 当前规则 |
|---|---|
| 质量过滤 | 候选质量至少为 0.02 |
| 小区域过滤 | 连通块至少包含 `max(64, floor(物体面积 × 3%))` 个像素 |
| 重叠像素归属 | 分配给 `质量 / √(候选面积 / 物体面积)` 最大的候选 |
| 再次清理 | 分配后删除过小连通块；失效候选移除后重新分配 |
| 数量限制 | 超过 6 个时，逐次删除 `当前区域面积 × √质量` 最低的候选，再重新分配 |

最终得到最多 6 个互不重叠的 mask，编号为 1、2、3……。这一步是本项目的后处理，不是 PartGLEE 官方的全景分割输出。

**物体内部可能仍有未被任何候选覆盖的像素，不会强行补齐。** 当前 UMD 设置关闭“禁止整物体”限制，允许功能区域覆盖大部分或整个物体。

## 4. Valen 接收什么

具体使用 **Valen-4B**，输入由**三个图片附件＋文字任务条件＋逐区域选择题**组成。三个图片附件来自同一帧：

| 图片 | 内容 | 用途 |
|---|---|---|
| 原色 RGB 裁剪图 | 原图按目标位置裁剪，保留原色及裁剪范围内的背景 | 判断真实形状、材质与内外表面 |
| 全部候选编号图 | 在同一裁剪图上叠加所有候选，颜色填充 45%，带描边与编号 | 对应区域编号、范围及相互位置 |
| 逐区域高亮拼图 | 每个小格保留整个物体，只高亮一个候选，最后拼成一张图 | 单独辨认各候选，减少标记遮挡 |

**Valen 的第一张图保留原背景；灰背景图用于 PartGLEE 的第二次分割。** 三张图来自同一个视角，不是三个独立样本。

当前 UMD 功能类别为：

`grasp / cut / scoop / contain / pound / support / wrap-grasp`

另外提供 `none` 拒选项。每个候选只能属于其中一类，颜色和编号没有预设功能含义。

文字任务条件包含每一类的**名称和定义**，以及总体判断规则；不是只把类别名称列出来。例如 `grasp` 强调专用手柄／抓握部位，`wrap-grasp` 强调手掌和手指环抱的物体外表面。

例如有 6 个候选，就同时提出 6 个选择题：“区域 1 的主要功能是什么？”……“区域 6 的主要功能是什么？”每题使用相同的七类定义及 `none` 说明。所有问题共享图片上下文，Valen 一次前向计算输出各选项概率，不逐 token 生成解释或 mask。

视觉输入对照保留这些文字条件：仅描边方案改变候选呈现；质心点方案的前两图不变，第三图换成 RGB＋单个候选质心点，并对每个候选独立调用 Valen。

## 5. 按功能合并 mask

对每个候选取概率最高的类别，再把同类候选做像素并集：

```text
候选 1 → grasp
候选 2 → cut
候选 3 → grasp

grasp mask = 候选 1 ∪ 候选 3
cut mask   = 候选 2
```

合并不要求区域相邻，也不填补空隙、扩张边界或重新分割。候选原本互斥且每个候选只有一类，因此最终每个像素最多只有一个功能类别。

输出与原始 RGB 像素对齐：

- `result/class_map.png`：类别 ID 图，0 为背景／未分配／none，1–7 为 UMD 功能类别。
- `result/masks/<类别>.png`：各类别的 0/255 二值 mask。
- `decisions.json`：候选编号、预测类别及各类别概率；概率是模型判断分数，不是实测准确率。
- `result/affordance_overlay.png`：功能 mask 叠加原始 RGB，供可视化检查。
- `foreground/object_mask.png`、`regions/unassigned_foreground.png`、`result/masks/none.png`：分别保留物体范围、未覆盖前景和判为 none 的候选，便于区分三者。

## 6. “GT 多数类别”诊断使用哪组 mask

使用第 3 步整理完成、**交给 Valen 判断之前的那组候选**，保留它们的边界和数量，仅替换分类结果：

```text
整理后的候选 mask
    → 统计各候选内部 GT 像素的类别数量
    → 每个候选取数量最多的类别
    → 将同类候选取并集
    → 与 GT 比较
```

它既不使用全部 50 个原始候选，也不使用 Valen 已经按预测类别合并后的 mask。

该诊断包含 GT 背景类别，忽略 void（−1）；多数票并列时优先保留原预测类别，否则取最小类别 ID。未被候选覆盖的像素仍为 0。

在原始 dominant GT、2,661 张测试图上，对应 **mIoU 81.95%、gIoU 75.49%**。这是使用 GT 的分类替换诊断，不能作为模型成绩，也不是严格的 mIoU 上限。

[查看全部样本的 GT 多数类别结果](../../outputs/umd_gt_majority_viewer/index.html)。

## 7. SFT 与 A/B/C 改动哪里

各方案固定同一套 PartGLEE 前景与候选，主要改变 Valen 的学习方式：

| 方案 | 改动 |
|---|---|
| 普通 SFT | 用 76 张训练图中候选的 GT 多数类别，训练决策头及语言模型 LoRA |
| A | 扰动编号、颜色、布局和定义表达；研究区域／定义配对与预测一致性 |
| B | 对候选做几何拆分／合并，加入组合监督；比较额外一致性约束 |
| C | 在三图输入基础上，显式提取目标候选特征；再研究邻近区域与整个物体的特征 |

A/B 的增强和辅助损失在训练阶段使用；推理仍按上述候选逐区分类。C 推理额外使用候选 mask 对第一张原色图的视觉 token 特征池化，但不修改候选边界。

原始零样本与 SFT 使用各自固定的功能定义：SFT 对混合候选强调选择占比最大的功能，二者配置分别为 `umd_affordances.json` 和 `umd_affordances_sft.json`。

具体结果见 [实验结果汇总](实验结果.md)。

### Prompt 中文翻译

实际请求由“共享说明＋三张图片＋每个候选一道选择题”组成。以下保留原始含义，相同的选项定义只展示一次。

**共享说明：**

> 请按照主要功能，对每个带编号的可见区域进行分类。
>
> 第一张图是没有颜色覆盖的 RGB 裁剪图；第二张图是在同一裁剪图上标出了编号 mask。颜色和编号属于标注，不是物体的真实外观。请利用 RGB 图像判断各编号 mask 内的表面。
>
> 使用提供的 UMD 功能定义，为每个带编号的可见区域分配一个主要功能。
>
> 区分专用手柄（grasp）与需要用手环抱握持的物体外表面（wrap-grasp）；区分凹形的舀取工作面（scoop）、储存内容物的腔体（contain）以及相对平坦的承托表面（support）。
>
> 对可见像素进行分类，并利用没有颜色覆盖的 RGB 区分内表面与外表面。不要仅因为某个区域可以触摸或握持，就把所有区域都标为 grasp。
>
> 如果符合给定定义，功能区域允许覆盖物体的大部分或全部，没有整物体面积限制。
>
> 如果没有功能定义匹配，或者区域混合了不兼容的功能部件，则选择 none。区域颜色及编号顺序不携带功能含义。
>
> 后面的拼图中，每个小格都在同一张 RGB 裁剪图上高亮一个候选区域。

**每道选择题附带的功能定义：**

| 选项 | 定义的中文翻译 |
|---|---|
| `grasp` | 用于握持和控制物体的专用手柄、握持部位或手指抓握区域。优先选择设计用于抓握的位置，而不是任意可触摸的工作面或容器的大面积外表面。 |
| `cut` | 用于切开材料的锋利刀片、刃口或切割工作面。不包括手柄及不承担切割作用的支撑结构。 |
| `scoop` | 通过舀取动作收集并提起松散或柔软材料的凹形工作面。应与较深的储存腔体及相对平坦的承托表面区分。 |
| `contain` | 主要用于容纳内容物的可见内表面或腔体表面。不包括独立手柄，以及用于环抱抓握的外表面。 |
| `pound` | 向其他材料施加冲击力的坚实撞击头或敲击工作面。不包括手柄和杆部。 |
| `support` | 从下方承托或运载材料的相对平坦工作面。应与凹形舀取面、储存腔体及手柄区分。 |
| `wrap-grasp` | 通过手指和手掌环绕握持的物体外表面。应与独立的专用手柄及可见的容纳腔体内表面区分。 |
| `none` | 标记像素无法可靠匹配上述七种功能、属于背景，或混合了不兼容的功能部件。这是拒选项，不是 UMD 的第八种功能。 |

对区域 **1～5** 分别提出下面这道题，选项定义相同：

> 对区域 **i**，根据提供的定义，选择且仅选择一个主要功能。判断被标记的像素；没有合适功能时选择 none。

### 该次实际预测

```text
区域 1 → wrap-grasp
区域 2 → grasp
区域 3 → scoop
区域 4 → none
区域 5 → none
```
